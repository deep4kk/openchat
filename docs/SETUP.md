# Setup guide: every key, where to get it, and how

AutoDM talks to **one external service only: Meta's official Instagram API**.
You need a Meta developer app and an Instagram professional account. Nothing else needs to be bought or signed up for.

| `.env` setting | What it is | Where it comes from |
|---|---|---|
| `INSTAGRAM_APP_ID` | Public ID of your Meta app's Instagram product | Meta App Dashboard (step 2) |
| `INSTAGRAM_APP_SECRET` | Secret used for login and to verify webhooks | Meta App Dashboard (step 2) |
| `APP_URL` | The public https address of your running app | You (step 4) |
| `WEBHOOK_VERIFY_TOKEN` | A password Meta echoes back when you register the webhook | Generated by `npm run setup` |
| `SESSION_SECRET` | Signs login cookies | Generated by `npm run setup` |
| `TOKEN_ENCRYPTION_KEY` | Encrypts Instagram tokens in the database | Generated by `npm run setup` |
| `DATABASE_URL` | Where data is stored | Preset to a local SQLite file |
| `ALLOWED_IG_USERNAMES` | Your Instagram username, without @. Only these accounts can log in | You |

There are **no Instagram access tokens to copy by hand.** You get your token automatically when you click "Continue with Instagram".
The app stores it encrypted and renews it before it expires.

> **Never commit `.env`.** It is already in `.gitignore`. If `INSTAGRAM_APP_SECRET` ever leaks, reset it in
> App Dashboard → App settings → Basic → App secret → Reset.

## 0. Requirements

- **Node.js 20.9 or newer** (https://nodejs.org). Check with `node -v`.
- An **Instagram Business or Creator account** that is **public**. Personal accounts can't use the API.
  Switch in the Instagram app: Settings → Account type and tools → Switch to professional account.
- In the Instagram app, allow message access:
  Settings → Messages and story replies → Message controls → Connected tools → **Allow access to messages: On**.
- A **Facebook account** to log in to Meta for Developers.

## 1. Install

```bash
git clone <this repo>
cd AutoDM
npm install
npm run setup     # creates .env with generated secrets + the local database
```

## 2. Create the Meta app → `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`

1. Go to https://developers.facebook.com/apps and click **Create app**. Register as a developer first if asked.
2. Name the app, then choose the use case **"Manage messaging & content on Instagram"**.
3. Pick (or skip) a business portfolio and finish creating the app.
4. In the left menu open **Use cases → Instagram → Customize → API setup with Instagram business login**.
5. At the top of that page you'll see **Instagram app ID** and **Instagram app secret** (click Show).
   Put them in `.env`:
   ```
   INSTAGRAM_APP_ID=...
   INSTAGRAM_APP_SECRET=...
   ```
   ⚠️ Use the **Instagram** app ID and secret from this page, **not** the "App ID" at the top of the dashboard
   (that one is the Facebook app ID and login will fail with it).

## 3. Add the permissions

On the same page, under **Permissions**, make sure these three are added:

- `instagram_business_basic` (read the account's profile and posts)
- `instagram_business_manage_comments` (receive comments, reply to them)
- `instagram_business_manage_messages` (send DMs, check if someone follows you)

The app asks for exactly these and nothing more.

## 4. Give the app a public https address → `APP_URL`

Meta only talks to **https** URLs reachable from the internet, so `http://localhost` alone won't work for login or webhooks.

- **On a server:** use your domain, e.g. `APP_URL=https://autodm.example.com`.
- **On your computer, for testing:** run a tunnel that forwards a public https URL to port 3000. Any tunnel works.
  Note that a tunnel is the one non-Meta tool in this guide; you only need it while testing locally.
  ```bash
  npm run dev                 # terminal 1
  ngrok http 3000             # terminal 2 (or: cloudflared tunnel --url http://localhost:3000)
  ```
  Copy the `https://....` address it prints into `APP_URL`, then restart `npm run dev`.
  Free tunnel addresses change each restart; update `APP_URL` and the Meta settings below when that happens.

**Always open the app through `APP_URL`** (not `localhost`), so the login cookie lands on the right address.
The app redirects you there automatically if you don't.

## 5. Register the login redirect and the data deletion URLs

Still under **API setup with Instagram business login**, open **Set up Instagram business login → Business login settings**:

| Field | Value |
|---|---|
| OAuth redirect URIs | `https://<APP_URL>/api/auth/instagram/callback` |
| Deauthorize callback URL | `https://<APP_URL>/api/meta/deauthorize` |
| Data deletion request URL | `https://<APP_URL>/api/meta/data-deletion` |

Save. The redirect URI must match `APP_URL` **exactly** (https, no trailing slash), or login fails with "Invalid redirect_uri".

## 6. Register the webhook → `WEBHOOK_VERIFY_TOKEN`

Same page, **Configure webhooks**:

1. **Callback URL:** `https://<APP_URL>/api/webhooks/instagram`
2. **Verify token:** the `WEBHOOK_VERIFY_TOKEN` value from your `.env` (generated by `npm run setup`).
3. Click **Verify and save**. The app must be running and reachable at that moment.
4. Subscribe to these fields: **comments**, **messages**, **messaging_postbacks**.

Every webhook Meta sends is checked against `INSTAGRAM_APP_SECRET`; unsigned or forged requests are rejected.

## 7. Add yourself as a tester and log in

While the app is in **Development** mode, only Instagram accounts with a role on the app can log in.

1. App Dashboard → **App roles → Roles → Add people → Instagram Tester**, and enter the Instagram username.
2. Accept the invite: on instagram.com go to **Settings → Website permissions → Apps and websites → Tester invites**.
3. Open `APP_URL` and click **Continue with Instagram**.

## 8. Privacy policy and app settings

App Dashboard → **App settings → Basic**:

- **Privacy policy URL:** `https://<APP_URL>/privacy`
- **Terms of service URL:** `https://<APP_URL>/terms`
- **User data deletion:** `https://<APP_URL>/api/meta/data-deletion` (callback URL), or the instructions page `https://<APP_URL>/data-deletion`.

Set `APP_NAME`, `OPERATOR_NAME` and `CONTACT_EMAIL` in `.env` first, so these pages say who runs the app, and read them
through. Meta reviewers check them. Put the app online with [DEPLOY.md](DEPLOY.md) (Vercel + Render) before App Review,
because a tunnel address changes and reviewers need a stable one.
- Add an app icon and category.

## 9. Going Live (needed for real comment webhooks)

Meta's documentation states:
- Apps must be in **Live** mode to receive webhook notifications.
- **Advanced Access** for `instagram_business_manage_comments` is required to receive `comments` webhooks.

So the **comment trigger only fires for real after**:

1. **Business verification** (App Dashboard → Settings → Business verification).
2. **App Review** for Advanced Access to the three permissions in step 3. Meta asks for a short screen recording
   of the flow and a description; explain that the app replies to comments that contain keywords the account owner chose,
   and sends the commenter the link they asked for.
3. Switching the app mode to **Live**.

Until then you can still test everything locally. See *Testing without App Review* below.

## Testing without App Review

- `npm test` runs the complete flow (comment → public reply → DM → follow check → link), plus all the safety rules,
  against a temporary database with the Instagram API simulated. No Meta account needed.
- After step 7 you can log in, load your real posts and reels in the editor, and create automations.
- In **Webhooks**, each field has a **Test** button that sends a sample payload, which confirms your URL and signature setup.
  Sample payloads use a fake account ID, so they don't match your account and nothing appears in the activity log;
  a `200` in your terminal means the webhook works.

## Troubleshooting

| Problem | Fix |
|---|---|
| Home page says "Almost there" with a list | Those `.env` values are empty. Fill them and restart. |
| "Invalid redirect_uri" on login | Redirect URI in step 5 must equal `APP_URL` + `/api/auth/instagram/callback` exactly. |
| "Invalid platform app" / "Invalid app ID" | You used the Facebook App ID. Use the **Instagram** app ID (step 2). |
| Logged in, then sent back to the home page | You opened the app on a different address than `APP_URL`. Open `APP_URL`. |
| Webhook "Verify and save" fails | App not running/reachable at `APP_URL`, or verify token doesn't match `.env`. |
| Comments don't trigger anything | App must be Live with Advanced Access (step 9); account must be public; the automation must be On and match the post and keyword. |
| Yellow "reconnect" banner on the dashboard | The Instagram login expired or was removed. Click *Reconnect Instagram*. Queued comments are kept for up to 7 days. |
| Activity shows "Waiting: hourly DM limit reached" | Working as intended: the safety cap is holding sends back. They go out automatically within the hour. |

## Optional settings

| Setting | Default | Meaning |
|---|---|---|
| `MAX_DMS_PER_HOUR` | 200 | Max comment-triggered DMs per account per hour (Meta's documented ceiling is 750). |
| `MAX_PUBLIC_REPLIES_PER_HOUR` | 100 | Max public comment replies per account per hour. Extra comments still get the DM. |
| `MIN_SEND_GAP_MS` | 2000 | Minimum pause between two sends on the same account. |
| `GRAPH_API_VERSION` | v23.0 | Instagram Graph API version. |
| `APP_NAME`, `OPERATOR_NAME`, `CONTACT_EMAIL` | none | Shown on the Privacy, Terms and Data deletion pages. Needed before App Review. |
| `SOURCE_CODE_URL` | none | Link to your repository in the footer. |
| `DISABLE_INLINE_WORKER` | off | `1` stops the website from sending; use when `npm run worker` runs separately. Automatic on Vercel. |
